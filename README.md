# Agent Harness Lab｜Agent Harness 工程学习笔记

从模型调用到可靠任务执行：通过持续演进的项目，研究 Agent Harness 的设计、实现、评测与前沿方法。

本项目围绕一个 AI 售后工单助手，研究一个脆弱 Demo 怎样逐步获得可靠的任务执行能力。学习过程不止于调用框架 API：每期定义问题、比较方法、阅读源码、实现机制，并通过真实实验检验选择。

> 当前阶段：课程规划与研究规范已建立。尚未发布课程正文、应用实现或实验结果；下方路线图不代表对应能力已经实现。

## 每一期研究什么

1. 要完成什么任务，怎样判断真正完成？
2. 当前系统为什么失败？
3. 最简单的合理方案是什么，还有哪些路线？
4. 为什么选择这一种，什么时候不应该使用？
5. 通用机制与框架实现有什么区别？
6. 实验能否证明改进，成本和退化在哪里？
7. 近期研究解决了什么，距离工程应用还有多远？
8. 尚未解决什么，下一步依据什么继续改进？

## 学习路线

- **建立最小闭环**：Agent 与 Workflow 的取舍、Harness 的职责、行动与反馈、完成判定。
- **持续推进任务**：状态恢复、工具设计与 MCP、信息获取、上下文与记忆、长任务交接。
- **可控与可改进**：规划与多 Agent、安全权限与人工接管、系统评测、失败归因、模型路由与预算。
- **按需进阶**：队列与背压、自托管推理、量化、基于执行证据的 Harness 优化。

评测、追踪、安全边界和执行预算从序章建立最低能力，再在后续专题深化。章节可以随研究密度拆分，不为凑固定期数压缩内容。

## 贯穿项目

AI 售后工单助手：接收问题 → 保存任务 → 获取政策和订单信息 → 选择动作 → 校验权限与参数 → 执行或转人工 → 核验结果 → 记录执行证据。

所有订单、政策和退款均使用教学数据及隔离模拟器，不操作真实资金。系统不能仅凭自然语言宣布完成；退款、状态变化和其他副作用必须有可核验的证据。

阶段结束会加入小型异领域迁移练习，检查学到的机制是否能用于资料研究、文件处理等其他任务，而不是只适用于售后场景。

## 研究与实验原则

- 先定义问题，再选框架；保留简单基线与不采用复杂方案的理由。
- 实现前检索方法和限制，定稿前更新论文、官方实现与版本。
- 优先一手资料，保存关键结论对应的证据与源码版本。
- 区分来源主张、源码行为、本地实验和推断。
- 每期制造失败，并保存真实命令、输出与对照结果。
- 前沿成果按证据与适用条件讨论，不把论文指标直接视为业务收益。
- 未运行、未复现、受环境阻塞的内容明确标注，不生成虚构日志或 benchmark。
