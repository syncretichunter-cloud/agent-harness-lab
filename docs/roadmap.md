# Agent Harness 工程学习笔记：逐期课程目录

## 课程目标

用一个持续演进的 AI 售后工单助手，研究从模型调用到可靠任务执行所需的机制，最终交付完整、可运行、可复现的工程项目。

面向掌握 Python 和基础 Web 开发、调用过模型 API 的读者。主线按先修顺序学习；扩展篇建立在完整主线之上，涉及模型服务与专用硬件时明确环境前提。

每期均包含问题与成因、现有方法及取舍、源码与实现、对照实验、相关近期研究、局限与改进方向。标题和交付目标明确；框架、论文、模型和方案结论依据当期研究与实验确定。下文“研究与改进”是研究问题，不是已获得的结论。

## 贯穿项目

业务流程：用户提交问题 → 保存工单 → 获取政策与订单信息 → 决定并校验动作 → 执行或转人工 → 核验结果 → 记录执行证据。

业务约束：订单归属正确、退款不超过实付、重复请求不重复退款、高风险动作审批、用户可以取消、每项副作用可审计。使用教学政策、订单及隔离的退款模拟器，不操作真实资金、不冒充真实平台集成。

从 00 起具备最小任务集、执行记录、预算与权限边界；后续逐期增强并运行累计回归。章节代码在同一项目中演进，最终版本可直接运行，章节 tag 保留可复现版本。

## 主线课程

### 00｜从模型调用到任务完成：Agent Harness 到底负责什么？

- **核心问题**：把文本回复误当成任务完成；为简单问题过度设计。
- **本期目标**：定义任务、环境、产物和完成标准，建立 baseline 与故障清单。
- **内容范围**：任务、结果与环境；程序、单次调用、Workflow 和 Agent 的边界。暂不展开复杂编排和推理优化。
- **方法比较**：普通程序、单次模型调用、固定 Workflow、Agent；解释人工处理的合理边界。
- **代码交付**：最小可启动应用、教学数据、任务结果断言、最小执行记录和调用预算；基线故障仅在隔离环境展示。
- **验收实验**：模型声称完成退款但数据库无记录，业务断言必须失败；对简单查询比较确定性程序与模型路径。 运行累计回归并记录真实结果。
- **研究与改进**：模型能力与外部控制的边界怎样测量？何时增加自主性有收益？
- **先修**：无。

### 01｜Agent 怎样行动、接收反馈并正确停止？

- **核心问题**：只会回复、工具调用后不检查、循环不止、虚假完成。
- **本期目标**：实现读取状态、选择动作、执行、观察、验证、停止的最小循环。
- **内容范围**：最小行动循环、观察反馈、完成判定、超时、步数预算和退出原因；不展开持久恢复与复杂规划。
- **方法比较**：固定状态转移、单次工具调用、ReAct 式循环；不要先上复杂规划器。
- **代码交付**：Agent 循环、结构化动作/观察、结果验证器和停止控制；保留确定性工具模拟器和真实模型适配边界。
- **验收实验**：工具持续未找到时，在预算内补问或转人工；成功声明必须有状态证据。 运行累计回归并记录真实结果。
- **研究与改进**：过程反馈、停止判定、反思/自纠正何时有效，何时只是增加调用？
- **先修**：00。

### 02｜任务中断后，怎样恢复执行而不重复操作？

- **核心问题**：进程退出丢进度；重试造成重复退款；完成结果写库前崩溃。
- **本期目标**：任务状态、幂等、Checkpoint、外部副作用核对和恢复。
- **内容范围**：持久状态、Checkpoint、幂等、结果核对与跨系统副作用；不假设本地数据库事务能覆盖所有外部系统。
- **方法比较**：请求重做、持久状态机、Checkpoint、持久工作流；比较本地事务与跨系统副作用边界。
- **代码交付**：持久任务仓储、状态迁移、幂等操作记录、恢复入口和故障注入测试。
- **验收实验**：执行前后分别杀进程，重启后不丢工单、不重复退款；工具结果未知时先核对外部状态。 运行累计回归并记录真实结果。
- **研究与改进**：长任务恢复和外部动作一致性的新方法有哪些，哪些只是已有分布式机制的应用？
- **先修**：01。

### 03｜从 Function Calling 到 MCP：工具怎样设计才好用？

- **核心问题**：能连通却不会选；工具重叠；错误无法修复；权限传递不清。
- **本期目标**：工具契约、描述、返回值、错误语义、执行环境和 MCP 接入。
- **内容范围**：工具契约、描述、参数/返回值、错误、发现与 MCP 连接；认证与隔离采用受支持实现，攻防体系在 08 深化。
- **方法比较**：本地函数、直接 API、MCP；细粒度/组合工具；一次暴露/按需发现；受限执行环境。
- **代码交付**：工具注册/执行接口、订单/物流/退款模拟工具、MCP 适配、超时与权限上下文传递。
- **验收实验**：缺参数、权限不足、超时、未知执行结果和含糊工具描述；检查模型是否正确修正或停止。 运行累计回归并记录真实结果。
- **研究与改进**：大规模工具检索、工具学习、代码执行式工具使用的收益与安全代价。
- **先修**：02。

### 04｜Agent 怎样获得可信信息：RAG、数据库还是实时查询？

- **核心问题**：静态塞全部材料、旧政策误用、动态订单数据被当作文档知识。
- **本期目标**：按信息类型选择检索、查询、实时读取，建立有效性与证据链。
- **内容范围**：信息分类、检索/查询取舍、版本有效期与引用；不把动态订单数据放进静态知识库，不扩成搜索技术全集。
- **方法比较**：直接上下文、关键词、向量、混合检索、重排、结构化查询、实时工具；比较是否需要 RAG。
- **代码交付**：政策导入和版本管理、简单检索基线与选定对照路线、结构化订单查询、证据关联和无答案处理。
- **验收实验**：新旧政策并存、精确订单查询、无答案、冲突证据；分别测检索与最终任务结果。 运行累计回归并记录真实结果。
- **研究与改进**：检索与长上下文的边界、检索规划、结构化/图信息获取及证据核验。
- **先修**：03。

### 05｜上下文不是越长越好：Agent 应该记住什么？

- **核心问题**：历史越堆越长、关键事实被截断、错误记忆污染、过期或冲突。
- **本期目标**：区分对话历史、任务状态、用户记忆、工作上下文和外部知识。
- **内容范围**：历史、任务状态、工作上下文、长期记忆的区别及写入/更新/遗忘；不把摘要等同于无损压缩。
- **方法比较**：滑动窗口、结构化状态、摘要、检索式记忆、按需读取；评估写入/更新/遗忘。
- **代码交付**：上下文构造器、Token 预算、记忆存取与冲突/过期处理、用户隔离测试。
- **验收实验**：大量无关历史下保留当前订单；纠正旧记忆；检查跨用户泄漏和压缩后事实丢失。 运行累计回归并记录真实结果。
- **研究与改进**：记忆选择、记忆演化、压缩保真、长上下文利用及投毒防护。
- **先修**：04。

### 06｜长任务怎样推进：拆解、交接与完成证据

- **核心问题**：状态恢复了却不知道下一步；重复劳动；计划写得完整但产物缺失。
- **本期目标**：子任务、进度记录、产物、检查清单、跨上下文交接。
- **内容范围**：进度、子任务、产物、跨上下文交接和阶段验收；本期不引入多 Agent 协调。
- **方法比较**：清单、任务图、进度文件、结构化产物、阶段验收；区别计划、尝试与已验证完成。
- **代码交付**：任务清单/进度协议、产物索引、交接与继续执行入口、分阶段结果核验。
- **验收实验**：在多步骤复杂工单中强制切换上下文；接手者能继续而非重做，完成项可核验。 运行累计回归并记录真实结果。
- **研究与改进**：长时程规划、交接摘要、产物驱动协调和可验证进展。
- **先修**：05。

### 07｜Workflow、规划与多 Agent：复杂任务该怎样组织？

- **核心问题**：固定流程处理不了变化，或多 Agent 带来不必要的开销与协调错误。
- **本期目标**：按任务结构选择协调方式，不默认自主性越高越好。
- **内容范围**：按任务可分解性选择固定流程、动态规划和委派；不把更多 Agent 当作默认升级。
- **方法比较**：确定性 Workflow、Router、单 Agent、Plan-and-Execute、多 Agent 委派；比较状态共享与隔离。
- **代码交付**：可对照的流程执行器、规划/重规划接口、受限委派与结果汇合；不适合采用的路线保留最小实验而不强塞进默认应用。
- **验收实验**：同一复合任务比较简单路线和复杂路线，测质量、成本、交接丢失及协调失败。 运行累计回归并记录真实结果。
- **研究与改进**：可分解性与多 Agent 收益、集中/分散协调、计划修正及相关错误。
- **先修**：06。

### 08｜Agent 能做什么、不能做什么：权限、安全与人工接管

- **核心问题**：提示注入、越权、凭据滥用、人工确认后参数改变、不能中途停止。
- **本期目标**：确定性业务校验、最小权限、隔离、审批、取消、补偿和审计。
- **内容范围**：威胁模型、确定性策略、动作授权、隔离、审批、取消和补偿；不承诺彻底消除提示注入。
- **方法比较**：Prompt 约束、Schema、策略引擎、能力权限、执行隔离和人工审批；职责分开。
- **代码交付**：策略校验、审批记录与参数绑定、取消/人工接管、审计和注入/越权回归用例。
- **验收实验**：恶意政策文档不能触发越权退款；审批绑定动作参数；取消后不再启动新副作用。 运行累计回归并记录真实结果。
- **研究与改进**：间接注入防御、动作级授权、风险识别及人机协作；说明防御假设和残余风险。
- **先修**：07。

### 09｜怎样评测 Agent：答得像样，还是任务真的完成？

- **核心问题**：只看答案观感，评测污染，过度依赖模型裁判，成功率掩盖危险副作用。
- **本期目标**：把累计任务集扩展为分层评测、回归和误差分析。
- **内容范围**：检索/回答/工具/任务分层评测、确定性断言与裁判、留出集及波动；深化从 00 就存在的测试。
- **方法比较**：确定性断言、人工标注、模型裁判、过程评估、环境状态验收；区分能力集与回归集。
- **代码交付**：任务评测执行器、开发/留出数据、质量/安全/成本/延迟报告、累计回归入口。
- **验收实验**：虚假完成、参数错、结果对但过程越权；重复执行报告波动，避免开发集充当留出集。 运行累计回归并记录真实结果。
- **研究与改进**：长时程评测、裁判可靠性、环境有效性、污染与 benchmark 外推边界。
- **先修**：08。

### 10｜Agent 为什么失败：用 Trace 找到根因并验证修复

- **核心问题**：只看到最后错误；把工具故障误判成模型能力问题；修改后不知道是否退步。
- **本期目标**：Logs/Metrics/Trace、版本关联、脱敏、失败分类与改进闭环。
- **内容范围**：跨模型/工具的关联追踪、版本与脱敏、错误分类、归因和单因素改进；不凭重放结果还原未知外部事实。
- **方法比较**：结构化日志、分布式 Trace、轨迹重放、人工错误分析和辅助诊断。
- **代码交付**：结构化 Trace/Span、脱敏和版本关联、失败分析与可控重放、修复前后回归报告。
- **验收实验**：注入检索错误、工具超时、上下文丢失等不同故障，检查诊断能否定位；单因素修改后回归。 运行累计回归并记录真实结果。
- **研究与改进**：轨迹归因、自动错误分类、基于执行证据的 Harness 优化；限制自动修改权限。
- **先修**：09。

### 11｜模型故障与预算限制下，Agent 怎样可靠运行？

- **核心问题**：单端点失败、无限重试、成本失控，降级后 Schema 或工具行为不兼容。
- **本期目标**：模型路由、Fallback、超时、重试/熔断和任务预算。
- **内容范围**：模型选择、兼容性、Fallback、限流、重试/熔断和任务预算；队列和自托管推理进入扩展篇。
- **方法比较**：固定模型、规则路由、质量路由、级联；同模型重试与换模型的边界。
- **代码交付**：模型适配/路由、兼容性校验、预算账本、故障切换与转人工/停止路径。
- **验收实验**：主模型 429/超时、备用模型不兼容、预算耗尽；仍守住任务和权限约束。 运行累计回归并记录真实结果。
- **研究与改进**：自适应测试时计算、路由学习、不确定性驱动升级及质量/成本前沿。
- **先修**：10。

### 12｜完整项目交付：从干净环境跑通端到端任务

- **核心问题**：单项功能通过不代表整个应用可安装、可运行、可验证，也不代表教程与最终源码一致。
- **本期目标**：完成集成和发布验收，交付可独立运行的最终版本，而不是片段合集。
- **内容范围**：配置、依赖锁、数据初始化/迁移、启动、测试/评测、版本与结果索引；说明部署前提和已知限制，不借总结期引入新的核心架构。
- **方法比较**：本机安装与容器化的环境/运维取舍；单元、集成、端到端验收各自覆盖与遗漏的错误。
- **代码交付**：完整应用源码、配置示例、教学数据、初始化/迁移、启动及测试/评测脚本、最终可运行版本和各期代码索引。核心流程没有未实现的占位逻辑。
- **验收实验**：从干净检出安装启动，完成查询、政策咨询、退款模拟与人工接管；再验证重复提交、中断恢复、权限拒绝和模型故障。核对持久状态与审计；运行完整回归和留出评测，报告质量、成本、延迟及限制。
- **研究与改进**：梳理在任务长度、分布变化、安全和资源约束下仍未解决的问题；用一个小型资料研究或文件处理任务检验机制可迁移性，不把单案例成功外推为通用可靠。
- **先修**：00—11。

## 扩展课程

### X01｜流量增加后，怎样排队、限流与处理过载？

- **核心问题与目标**：控制并发、优先级、重试队列、死信、至少一次投递和幂等消费。
- **内容范围**：任务队列、Worker、优先级、背压、死信和至少一次投递；不重复讲模型内批处理。
- **方法比较**：直接限流、队列/Worker、不同持久队列；按一致性和运维成本选择。
- **代码交付**：队列/Worker、并发与优先级控制、重试/死信、幂等消费和压力测试脚本。
- **验收实验**：可配置并发工单，不丢不重，报告等待时间、尾延迟、取消和过载恢复。 报告外部条件和未验证项，不以合成指标替代真实运行。
- **研究与改进**：Agent 工作负载调度、截止时间/预算感知调度。
- **先修与环境**：00—12。

### X02｜自托管推理怎样影响 Agent 的延迟与吞吐？

- **核心问题与目标**：理解 Prefill/Decode、KV Cache、批处理、缓存及 TTFT/TPOT。
- **内容范围**：Prefill/Decode、KV Cache、批处理、TTFT/TPOT 和服务选型；按条件选择实现，不要求同时部署所有引擎。
- **方法比较**：云 API 与本地服务；对照 vLLM、SGLang、TensorRT-LLM 的具体版本与适配条件，不默认全部部署。
- **代码交付**：选定推理服务的启动配置、模型适配、单请求/并发基准、环境清单与任务质量对照。
- **验收实验**：相同模型/数据的单请求与并发对照，记录硬件、吞吐、端到端延迟和任务质量。 报告外部条件和未验证项，不以合成指标替代真实运行。
- **研究与改进**：缓存复用、推测解码、分离式服务等；以当前官方材料确认。
- **先修与环境**：00—12；可用模型权重、许可与计算资源。

### X03｜量化之后，Agent 还会正确调用工具和完成任务吗？

- **核心问题与目标**：比较精度、内存、速度和业务质量，不把格式与算法混为一谈。
- **内容范围**：精度/格式/算法的区别，资源节省与任务质量；不以一般对话观感代替业务评测。
- **方法比较**：Weight-only/PTQ、AWQ/GPTQ、不同精度及 GGUF/llama.cpp 路线；核对模型和硬件支持。
- **代码交付**：原精度/量化配置、资源与速度对照脚本、复用任务集的精度回归报告。
