# Agent Harness 工程学习笔记：问题驱动蓝图

## 定位

系列名：Agent Harness 工程学习笔记。
长文总标题可用：从模型调用到 Agent Harness：做一个能可靠完成任务的 AI 应用。

面向会 Python/基础 Web 开发、调用过模型 API 的读者。用持续演进的 AI 售后工单助手，研究任务闭环、可靠性、信息获取、执行控制和系统改进。不要求预先掌握 Kubernetes、CUDA 或分布式训练。

每期研究什么任务、为什么失败、现有路线与选择、源码机制、真实实验、近期研究与局限、改进方向。阅读资料不是装饰，做出有证据的选择才是目标。

本文件是课程与逐期研究任务规划，不是已完成的文献综述。下面的“研究问题”都需要单期生产时在线检索；不能当成已有研究结论。详细证据模板见 episode-research-workflow.md。

## 项目及贯穿约束

AI 售后工单助手支持物流、政策咨询、退款、换货和转人工，连接政策库、订单/物流工具、退款模拟器、人工队列。

订单必须属于当前用户；退款不超过实付；重复请求不重复退款；高风险操作审批；副作用有审计与完成证据；不能凭自然语言宣布完成。业务规则和数据为教学示例，不冒充真实平台政策。默认使用本地沙箱与模拟退款，不操作真实资金。

序章建立小型固定任务集、最小 Trace、预算/超时/取消和关键权限边界。初始脆弱版本的缺陷在隔离环境展示，不把不安全 Demo 暴露成公共服务。后续每期运行累计回归集。

每期比较简单方法与必要的复杂方法；相关研究进入每期，不把前沿研究只放进最后一章。各部分为学习单元，可按密度拆讲，不预先硬锁期数。

## 第一部分：定义任务，建立最小闭环

### A0 序章：什么时候需要 Agent，Harness 负责什么
- 做什么：定义任务、环境、产物和完成标准，建立 baseline 与故障清单。
- 解决什么：把文本回复误当成任务完成；为简单问题过度设计。
- 方法比较：普通程序、单次模型调用、固定 Workflow、Agent；解释人工处理的合理边界。
- 实验：模型声称完成退款但数据库无记录，业务断言必须失败；对简单查询比较确定性程序与模型路径。
- 研究问题：模型能力与外部控制的边界怎样测量？何时增加自主性有收益？
- 产物/依赖：基线仓库、任务集、成本与质量基线、最小记录；无前置。

### A1 Agent 怎样行动、接收反馈并正确停止
- 做什么：实现读取状态、选择动作、执行、观察、验证、停止的最小循环。
- 解决什么：只会回复、工具调用后不检查、循环不止、虚假完成。
- 方法比较：固定状态转移、单次工具调用、ReAct 式循环；不要先上复杂规划器。
- 实验：工具持续未找到时，在预算内补问或转人工；成功声明必须有状态证据。
- 研究问题：过程反馈、停止判定、反思/自纠正何时有效，何时只是增加调用？
- 产物/依赖：最小循环与退出原因记录；依赖 A0。先用隔离工具桩，后续替换。

## 第二部分：让任务持续推进

### B1 任务中断后，怎样恢复且不重复执行
- 做什么：任务状态、幂等、Checkpoint、外部副作用核对和恢复。
- 解决什么：进程退出丢进度；重试造成重复退款；完成结果写库前崩溃。
- 方法比较：请求重做、持久状态机、Checkpoint、持久工作流；比较本地事务与跨系统副作用边界。
- 实验：执行前后分别杀进程，重启后不丢工单、不重复退款；工具结果未知时先核对外部状态。
- 研究问题：长任务恢复和外部动作一致性的新方法有哪些，哪些只是已有分布式机制的应用？
- 产物/依赖：状态表、迁移、恢复测试；依赖 A1。

### B2 工具怎样设计、连接并安全执行
- 做什么：工具契约、描述、返回值、错误语义、执行环境和 MCP 接入。
- 解决什么：能连通却不会选；工具重叠；错误无法修复；权限传递不清。
- 方法比较：本地函数、直接 API、MCP；细粒度/组合工具；一次暴露/按需发现；受限执行环境。
- 实验：缺参数、权限不足、超时、未知执行结果和含糊工具描述；检查模型是否正确修正或停止。
- 研究问题：大规模工具检索、工具学习、代码执行式工具使用的收益与安全代价。
- 产物/依赖：工具注册与执行层、权限上下文、审计；依赖 B1，继承已有循环。

### B3 当前任务的信息应从哪里来
- 做什么：按信息类型选择检索、查询、实时读取，建立有效性与证据链。
- 解决什么：静态塞全部材料、旧政策误用、动态订单数据被当作文档知识。
- 方法比较：直接上下文、关键词、向量、混合检索、重排、结构化查询、实时工具；比较是否需要 RAG。
- 实验：新旧政策并存、精确订单查询、无答案、冲突证据；分别测检索与最终任务结果。
- 研究问题：检索与长上下文的边界、检索规划、结构化/图信息获取及证据核验。
- 产物/依赖：政策版本与有效期、检索评测；依赖 B2。

### B4 上下文和记忆该保留什么
- 做什么：区分对话历史、任务状态、用户记忆、工作上下文和外部知识。
- 解决什么：历史越堆越长、关键事实被截断、错误记忆污染、过期或冲突。
- 方法比较：滑动窗口、结构化状态、摘要、检索式记忆、按需读取；评估写入/更新/遗忘。
- 实验：大量无关历史下保留当前订单；纠正旧记忆；检查跨用户泄漏和压缩后事实丢失。
- 研究问题：记忆选择、记忆演化、压缩保真、长上下文利用及投毒防护。
- 产物/依赖：上下文预算与记忆生命周期；依赖 B3。

### B5 长任务怎样拆解、交接并保留完成证据
- 做什么：子任务、进度记录、产物、检查清单、跨上下文交接。
- 解决什么：状态恢复了却不知道下一步；重复劳动；计划写得完整但产物缺失。
- 方法比较：清单、任务图、进度文件、结构化产物、阶段验收；区别计划、尝试与已验证完成。
- 实验：在多步骤复杂工单中强制切换上下文；接手者能继续而非重做，完成项可核验。
- 研究问题：长时程规划、交接摘要、产物驱动协调和可验证进展。
- 产物/依赖：进度协议、产物索引、交接测试；依赖 B4。

### 阶段迁移练习

将恢复、信息获取或交接机制中的一项用于小型资料研究/文件处理任务，检查机制是否独立于退款业务。不另维护第二套完整项目。

## 第三部分：让自主执行可控、可改进

### C1 什么时候用工作流、动态规划或多 Agent
- 做什么：按任务结构选择协调方式，不默认自主性越高越好。
- 解决什么：固定流程处理不了变化，或多 Agent 带来不必要的开销与协调错误。
- 方法比较：确定性 Workflow、Router、单 Agent、Plan-and-Execute、多 Agent 委派；比较状态共享与隔离。
- 实验：同一复合任务比较简单路线和复杂路线，测质量、成本、交接丢失及协调失败。
- 研究问题：可分解性与多 Agent 收益、集中/分散协调、计划修正及相关错误。
- 产物/依赖：选择规则、协调协议、可取消任务；依赖 B5。

### C2 怎样限制权限并让人接管
- 做什么：确定性业务校验、最小权限、隔离、审批、取消、补偿和审计。
- 解决什么：提示注入、越权、凭据滥用、人工确认后参数改变、不能中途停止。
- 方法比较：Prompt 约束、Schema、策略引擎、能力权限、执行隔离和人工审批；职责分开。
- 实验：恶意政策文档不能触发越权退款；审批绑定动作参数；取消后不再启动新副作用。
- 研究问题：间接注入防御、动作级授权、风险识别及人机协作；说明防御假设和残余风险。
- 产物/依赖：威胁模型、策略测试与接管路径；依赖 C1，深化序章已有边界。

### C3 怎样证明系统变好了，而不是碰巧答对
- 做什么：把累计任务集扩展为分层评测、回归和误差分析。
- 解决什么：只看答案观感，评测污染，过度依赖模型裁判，成功率掩盖危险副作用。
- 方法比较：确定性断言、人工标注、模型裁判、过程评估、环境状态验收；区分能力集与回归集。
- 实验：虚假完成、参数错、结果对但过程越权；重复执行报告波动，避免开发集充当留出集。
- 研究问题：长时程评测、裁判可靠性、环境有效性、污染与 benchmark 外推边界。
- 产物/依赖：评测规范、留出集与回归报告；依赖 C2，不替代前期已有测试。

### C4 从一次失败找到根因，再验证改进
- 做什么：Logs/Metrics/Trace、版本关联、脱敏、失败分类与改进闭环。
- 解决什么：只看到最后错误；把工具故障误判成模型能力问题；修改后不知道是否退步。
- 方法比较：结构化日志、分布式 Trace、轨迹重放、人工错误分析和辅助诊断。
- 实验：注入检索错误、工具超时、上下文丢失等不同故障，检查诊断能否定位；单因素修改后回归。
- 研究问题：轨迹归因、自动错误分类、基于执行证据的 Harness 优化；限制自动修改权限。
- 产物/依赖：失败档案、修复前后证据和回滚；依赖 C3，深化已有 Trace。

### C5 在质量、预算和可用性之间怎样选择
- 做什么：模型路由、Fallback、超时、重试/熔断和任务预算。
- 解决什么：单端点失败、无限重试、成本失控，降级后 Schema 或工具行为不兼容。
- 方法比较：固定模型、规则路由、质量路由、级联；同模型重试与换模型的边界。
- 实验：主模型 429/超时、备用模型不兼容、预算耗尽；仍守住任务和权限约束。
- 研究问题：自适应测试时计算、路由学习、不确定性驱动升级及质量/成本前沿。
- 产物/依赖：预算账本、兼容性回归、停止/转人工规则；依赖 C4。

### 阶段总结

交付完整闭环、质量/安全/成本报告和代码索引。再做一个轻量迁移任务。讨论剩余限制而非宣称达到生产就绪；无流量、运维或自托管需求时不强推基础设施支线。

## 按需进阶支线

### X1 流量增加后，怎样排队与背压
- 目标/问题：控制并发、优先级、重试队列、死信、至少一次投递和幂等消费。
- 方法：直接限流、队列/Worker、不同持久队列；按一致性和运维成本选择。
- 实验：可配置并发工单，不丢不重，报告等待时间、尾延迟、取消和过载恢复。
- 研究问题：Agent 工作负载调度、截止时间/预算感知调度。
- 前提：先有 C5 的质量与预算基线，确有吞吐需求。

### X2 自托管推理怎样影响任务体验
- 目标/问题：理解 Prefill/Decode、KV Cache、批处理、缓存及 TTFT/TPOT。
- 方法：云 API 与本地服务；对照 vLLM、SGLang、TensorRT-LLM 的具体版本与适配条件，不默认全部部署。
- 实验：相同模型/数据的单请求与并发对照，记录硬件、吞吐、端到端延迟和任务质量。
- 研究问题：缓存复用、推测解码、分离式服务等；以当前官方材料确认。
- 前提：确有自托管需求及硬件；缺硬件就报告未验证，不编 benchmark。

### X3 量化节省资源之后，能力是否仍够用
- 目标/问题：比较精度、内存、速度和业务质量，不把格式与算法混为一谈。
- 方法：Weight-only/PTQ、AWQ/GPTQ、不同精度及 GGUF/llama.cpp 路线；核对模型和硬件支持。
- 实验：同任务集对照原精度与量化，观察工具参数、复杂任务、安全和性能退化。
- 研究问题：低比特、激活/KV 量化、混合精度及任务敏感度。
- 前提：已有可复现推理环境和评测，不用一般聊天观感代替任务测试。

### X4 Harness 能否根据失败自动改进
- 目标/问题：区分 Prompt 调整、工具优化、流程搜索和整个系统优化。
- 方法：人工单因素迭代、离线搜索、反馈驱动优化；保留留出集、预算和回滚。
- 实验：限制可修改范围，对训练/开发任务优化后用留出集验证，并测试安全退化。
- 研究问题：Harness 自动演化、轨迹反馈、记忆演化与过拟合控制。
- 前提：C3/C4 的评测和归因可靠；研究原型不等于可上线自动修改。

## 最终工程验收

系列最终必须交付完整、可运行、可复现的项目，不以文档、局部代码片段或空壳骨架作为终点。主线能力集成到同一个端到端应用，进阶实验有独立运行入口并明确外部条件。

- 完整业务与 Harness 源码，不遗留阻断承诺流程的 TODO、占位函数或假成功返回。
- 依赖锁定、配置示例、教学数据、数据库初始化/迁移、启动和评测脚本齐备。
- 干净检出后按文档安装与配置，可启动服务、完成示例任务并核验持久结果。
- 单元/集成/失败恢复测试及累计任务评测真实通过，保存环境和命令。
- 最终版本可直接运行，章节 tag 可回看演进；教程、代码和复现结果相互对应。
- 需要模型服务、凭据或专用硬件的能力明确说明前提；隔离业务模拟器明确标注，不能冒充真实平台集成。
