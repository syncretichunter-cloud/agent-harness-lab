# 单期研究、证据与实验工作流

## 一、研究前先定义问题

输入：本期学习单元、目标读者、已有代码/tag、前期产物、执行环境和可用预算。
输出：任务定义、故障和根因假设、最简单基线、候选路线、可检验主张、实验计划。

先明确任务成功条件，不先决定必须用某个框架。分清模型、上下文、工具、控制流、外部系统和评价标准各自可能导致的故障。

## 二、第一轮检索：方法地图

按照问题形成中英文检索词，组合以下方向：
- 原始定义、协议、算法和代表论文；
- 官方实现、源码、测试和维护者工程解释；
- limitation、failure、issue、ablation、negative result 等限制与相反证据；
- 最近相关研究及相应代码、复现和争议。

时间范围先覆盖近期，再按需要向前追溯，不为追新遗漏奠基方法。不预设每期一定存在新论文。只找到摘要时不能当成全文读过；检索空或结果过窄要换关键词、扩时间或追踪引用。

技术结论优先一手材料。博客、社媒可发现线索，不能用传播热度判断正确。Issue 是特定版本/环境的观察，不自动代表普遍缺陷。

研究完成的信号：解释得清简单基线、主要替代路线、关键假设、反例/限制、为何选择和哪些证据会推翻选择。来源数量只是最低保障。

## 三、证据账本

每个重要结论记录：
- claim_id 与具体主张；
- 标题、作者/机构、URL；
- 发布/更新日期、访问日期；
- 论文版本、协议版本、release 或 commit SHA；
- 具体章节、文件/符号或实验位置；
- 来源实际支持什么，不支持什么；
- 标签：来源主张 / 源码行为 / 本地实验 / 推断；
- 争议、矛盾来源与置信限制。

性能数字额外记录模型、硬件、精度、数据集、并发、预算、采样和软件版本。不能把不同条件的数字直接横比。官方宣传也需标注为项目方报告，不能冒充独立验证。

源码锚点至少包含 repo@commit、file、symbol、控制流/数据变化、错误分支、相关测试与本项目差异。源码浏览不等于本地运行。

## 四、方法比较

对每条与任务有关的路线，写：
- 核心机制和前提；
- 能解决的问题与不能解决的问题；
- 任务质量、延迟、成本、复杂度、权限风险和维护负担；
- 证据和未知项；
- 不采用条件、升级触发条件。

保留不新增组件的简单基线；没有测量就不填伪精确数字或打分。不要为凑数机械比较所有技术。

选择记录：当前选择 → 理由 → 放弃路线与理由 → 可推翻此判断的实验 → 下一步。

## 五、近期研究卡

对直接相关成果分别记录：
- 它解决本期哪个具体缺陷？
- 相比工程基线改了什么机制？
- 实验覆盖的任务、模型、环境、预算与评价标准；
- 结果是作者报告还是已有独立验证？
- 代码/数据/权重是否公开，能否实际运行？
- 是否做消融、跨任务/跨模型验证，已知负面结果是什么？
- 与本项目的假设差异、集成成本和上线障碍；
- 当前成熟度与本期处理方式。

成熟度按证据判断：
- 工程已验证：有对应场景的实现、稳定性和使用证据，仍需核对适用条件。
- 可试验：机制与实现可检查，具备复现条件，但工程价值尚待本项目验证。
- 待验证假设：证据或复现不足，只作为研究方向。

开源不自动等于成熟；没开源不自动等于无效；新论文不自动等于新方法；不能以论文 benchmark 提升代替业务收益。

未找到直接相关近期成果时记录查询范围、所见最相关材料和缺口，不伪造、不塞无关论文。

## 六、实验设计与真实执行

先写可证伪主张，例如：在相同任务集和预算约束下，减少重复执行且不降低完成率。

实验记录包括：
- 改造前 commit/tag、依赖锁和数据版本；
- 实验/对照的差别和公平性条件；
- 业务断言、负面副作用、成本、延迟和人工介入；
- 初始状态、触发操作、预期及真实结果；
- 真实命令、输出文件、日志和产物位置；
- 随机性、运行次数、采样配置及不确定性；
- 失败与非预期退化；
- 是否满足本期验收，而不是只检查程序不报错。

尽可能只改变一个因素；适用时做消融、重复测试和小型迁移。若资源不足，报告有限样本与未验证项，不把单次成功外推。

数据分为开发与留出；优化时不能不断查看留出集后继续把它当未知测试。合成数据标注来源和构造方式，不伪装真实用户数据。真实业务数据需脱敏并确认使用权限。

实验使用隔离模拟器，限制工具范围、调用数、费用、超时；禁止为演示执行真实退款。外部副作用需要核验实际状态，超时不能直接等同于未执行。

## 七、第二轮检索：定稿更新

初稿与实验后再检索：
- 关键论文是否有更新/勘误；
- 官方实现、协议、依赖和已知问题是否变化；
- 是否出现直接相关新研究或反例；
- 新证据是否改变选型、表述或实验。

记录研究截止日期。变化影响核心行为时更新代码和回归，不只换一个引用链接。未完成本轮不能声称“已核对最新”。

## 八、可复用单期档案模板

```markdown
# 本期标题 / 单元 ID
状态：规划 / 研究中 / 实现中 / 已验证 / 部分阻塞
研究截止日期：待核实

## 读者先修与本期任务
输入、环境、产物、成功条件、约束；不讨论什么。

## 失败与根因
复现；根因假设；其他可能解释。

## 改造前基线
代码/data 版本；任务集；指标；已知缺陷。

## 方法地图与选择
简单基线；候选路线；条件/代价/限制/证据；选择与可推翻条件。

## 检索记录与证据账本
首轮/更新轮查询；来源；日期/版本；主张对应证据与争议。

## 源码锚点
repo@commit；文件/符号；实际行为；测试；边界。

## 最小实现与项目改造
接口变化；迁移；框架承担什么；安全边界。

## 实验计划与真实结果
对照；业务断言；命令和产物；费用/延迟；失败/退化；未验证项。

## 近期研究
具体缺陷；新机制；证据条件；成熟度；复现状态；落地差距。

## 当前工程判断
何时采用/不采用；升级触发条件；尚未解决的问题。

## 依赖与下一期接口
沿用的能力、数据、代码/tag；下一期需要什么。
```

## 九、验收与失效检查

研究合格：问题清楚、比较公平、证据可定位、近期成果有相关性与成熟度判断、实验能检验选择。

整期合格：再加真实代码、失败测试、对照结果、可复现产物、边界和正文。

典型不合格：先指定框架再找背书；只有来源列表没有结论对应；把 README 当源码；堆论文不解释与任务的关系；无基线宣称提升；编造运行结果；把计划里的研究方向说成研究发现。
